# Agent Vault Sync 用户说明与使用手册

文档适用版本：`0.5.0`
最后更新：2026-08-27

## 1. 这是什么

Agent Vault Sync 是一个本地优先的长期记忆与 Skill 复用工具。它让不同电脑、不同厂商的 AI Agent 使用同一份个人记忆，而不要求用户部署云数据库或持续运行一台服务器。

最简单的使用方式是：

1. 在 iCloud Drive、OneDrive、Dropbox、Syncthing 或 NAS 中创建一个 `AgentVault` 文件夹。
2. 在每台电脑安装 `agent-vault` 命令。
3. 把每台电脑上的 Codex、Claude Code、Cursor 等 Agent 连接到这个文件夹。
4. Agent 通过 MCP 工具保存和召回长期信息；网盘负责在电脑之间同步普通文件。

它解决的是下面这类问题：

- 在 Codex 中告诉 Agent“我偏好简洁的中文回答”，换到 Cursor 后仍可召回。
- 在公司电脑确定一个项目技术决策，回到家用另一种 Agent 时仍能查到。
- 将自己编写的工作流程 Skill 放在一个地方，再分发给多个 Agent 使用。
- 离线工作时照常保存记忆，网络恢复后由同步软件传到其他设备。
- 不想为个人记忆部署服务器、注册数据库服务或承担持续的云端费用。

## 2. 它不是什么

为了避免误解，当前版本不是：

- 聊天记录备份工具。它不会自动扫描或上传全部历史对话。
- 大模型或 Agent 本身。它只提供记忆存储、检索、MCP 和 Skill 分发。
- 云端记忆服务。项目不提供账号系统和托管服务器。
- 密码管理器。0.5.0 没有端到端加密，严禁保存密码、Token、私钥和恢复码。
- 托管向量数据库。检索可选使用本机 Ollama 进行语义召回，Ollama 不可用或语义检索关闭时会回退到本地 Unicode/CJK 文本检索。
- 强一致的多人协作数据库。同一条记忆被多台设备并发修改时，会确定性选择一个最终版本，而不会自动理解并合并两段文字。

## 3. 核心概念

### 3.1 Vault

Vault 是放在同步目录中的共享文件夹，也是所有记忆和共享 Skill 的唯一数据源。

典型结构如下：

```text
AgentVault/
├── agent-vault.json
├── memory/
│   └── events/
│       └── <device-id>/
│           └── <date>/
│               └── <event-id>.json
└── skills/
    └── <skill-name>/
        └── SKILL.md
```

Vault 中不放正在运行的 SQLite 数据库、WAL 文件或数据库锁。每次新增、修改、删除都会生成一个单独的不可变 JSON 事件，因此两个设备同时新增记忆时，不需要争抢同一个数据库文件。

### 3.2 本机状态

每台电脑还会保存少量不同步的本机状态，默认位置是：

```text
~/.agent-vault-sync/state.json
```

它记录：

- 当前默认使用哪个 Vault。
- 这台设备在每个 Vault 中的设备 ID。
- 最近使用的混合逻辑时钟。

这些内容不应放进网盘。其他电脑会生成自己的设备 ID。

### 3.3 Memory

每条记忆包含稳定 ID、正文、可选标题、类型、作用域、标签、来源和时间信息。

支持的记忆类型：

| 类型 | 用途 | 示例 |
|---|---|---|
| `fact` | 相对稳定的事实 | “生产服务器使用 Ubuntu 24.04” |
| `preference` | 用户偏好 | “回答使用简体中文” |
| `decision` | 已确定的选择 | “这个项目使用 npm” |
| `lesson` | 经验与教训 | “Windows 下不要依赖符号链接分发 Skill” |
| `note` | 普通长期笔记 | “下次需要检查同步延迟” |
| `task` | 需要跨会话保留的任务 | “为项目补充 Windows 实机测试” |

支持的作用域：

| 作用域 | 用途 | 是否建议填写 `scope-id` |
|---|---|---|
| `global` | 对所有 Agent 和项目都适用 | 通常不需要 |
| `project` | 只与某个项目有关 | 建议填写项目名 |
| `agent` | 只与某类 Agent 有关 | 建议填写 Agent 名称 |

作用域目前用于记录和筛选，不是访问控制。`project` 记忆依然存放在同一个 Vault 中。

### 3.4 MCP

MCP Server 是 Agent 与 Vault 之间的统一接口。无论前端是 Codex、Claude Code 还是 Cursor，看到的都是同一组记忆工具。

读取类 MCP 工具带有标准只读注解；保存、更新和删除仍是写操作，某些 Agent 会根据自己的安全策略要求用户批准。

### 3.5 Skill

Skill 是可复用的 Agent 工作说明。Vault 中的 `skills/` 是源目录，`agent-vault skills sync` 会把 Skill 按内容哈希复制到各 Agent 的本机 Skill 目录。

这里使用复制而不是符号链接，是为了兼容 Windows、OneDrive 和部分 NAS。不要直接修改 Agent 目录中的副本，因为下一次同步可能替换整个副本目录；应始终修改 Vault 中的源 Skill。

## 4. 支持范围

当前提供以下适配器：

| Agent | MCP 配置位置 | Skill 目标位置 | 适配状态 |
|---|---|---|---|
| OpenAI Codex | `~/.codex/config.toml` | `~/.agents/skills` | 已在 macOS 实机验收 |
| Claude Code | `~/.claude.json` | `~/.claude/skills` | 配置安装测试通过 |
| Cursor | `~/.cursor/mcp.json` | `~/.cursor/skills` | 配置安装测试通过 |
| OpenCode | `~/.config/opencode/opencode.json` | `~/.agents/skills` | 配置安装测试通过 |
| DeepSeek Harness | `$DSH_HOME/cordis.patch.yml` | `~/.agents/skills`、`$DSH_HOME/skills` | Cordis 配置测试通过 |
| Gemini CLI | `~/.gemini/settings.json` | `~/.gemini/skills` | 配置安装测试通过 |
| GitHub Copilot CLI | `~/.copilot/mcp-config.json` | `~/.copilot/skills` | 配置安装测试通过 |
| MiniMax Code | `$MINIMAX_DATA_DIR/plugins/agent-vault/mcp.json` | Agent Plugin 内的 `skills/` | Agent Plugins 1.0 配置测试通过 |

当前发布包已在 macOS 上完成 CLI、MCP 和可视化控制台实机验收。源码提供 Windows 路径处理、Windows 原生目录选择器和 GitHub Actions Windows/Node.js 20、22 测试矩阵，但 0.5.0 尚未完成独立 Windows 电脑的人工验收。

## 5. 系统要求

- macOS 或 Windows。
- Node.js 20 或更高版本。
- 至少一种受支持的 Agent；也可以只使用 CLI。
- 一个可双向同步的普通文件夹，或者拥有读写权限的 NAS 挂载目录。

检查 Node.js：

```bash
node --version
npm --version
```

如果 `node --version` 低于 20，应先升级 Node.js。

## 6. 安装 Agent Vault Sync

### 6.1 Windows 单文件 EXE（推荐）

Windows x64 用户可以使用 `AgentVault.exe`，不需要另外安装 Node.js、npm 或 `node_modules`。EXE 内含 Node.js 运行时、CLI、MCP Server 和可视化控制台。

把文件复制到 Windows 后，不要直接从“下载”目录接入 Agent。先放到固定位置：

```powershell
$folder = "$env:LOCALAPPDATA\AgentVault"
New-Item -ItemType Directory -Force $folder
Copy-Item "$env:USERPROFILE\Downloads\AgentVault.exe" "$folder\AgentVault.exe"
Set-Location $folder
```

验证版本：

```powershell
.\AgentVault.exe --version
```

双击 `AgentVault.exe`，或者在 PowerShell 运行：

```powershell
.\AgentVault.exe
```

无参数启动会自动打开可视化控制台。其他命令与 npm 版本一致：

```powershell
.\AgentVault.exe status
.\AgentVault.exe recall "中文偏好"
.\AgentVault.exe ui --port 47831
.\AgentVault.exe agents install codex
```

Agent MCP 配置会记录 EXE 的绝对路径。接入 Agent 后如果移动、重命名或删除 EXE，MCP 将无法启动；应回到新位置运行控制台并点击该 Agent 的“刷新”。

发布边界：

- 当前产物是 Windows x64 控制台程序；Windows ARM64 尚未单独发布。
- EXE 是自包含文件，体积约 84 MB 属正常现象。
- 当前没有商业代码签名证书，Windows 可能显示“未知发布者”。先核对 SHA-256，只允许这一个经过核验的文件，不要关闭 SmartScreen 或系统级安全防护。
- Mac 可以生成并检查 Windows PE 文件，但最终运行仍应在真实 Windows 或 Windows CI 中验收。

### 6.2 从 npm 安装包安装

进入安装包所在目录，执行：

```bash
npm install -g ./agent-vault-sync-0.5.0.tgz
```

Windows PowerShell 使用相同命令：

```powershell
npm install -g .\agent-vault-sync-0.5.0.tgz
```

### 6.3 从源码安装

```bash
npm install
npm run build
npm link
```

### 6.4 验证安装

```bash
agent-vault --version
agent-vault --help
```

预期版本为：

```text
0.5.0
```

## 7. 选择同步目录

建议为 Vault 创建独立目录，不要直接把整个网盘根目录当成 Vault。

| 场景 | 示例目录 |
|---|---|
| macOS iCloud Drive | `$HOME/Library/Mobile Documents/com~apple~CloudDocs/AgentVault` |
| Windows OneDrive | `$env:OneDrive\AgentVault` |
| Windows OneDrive 备用路径 | `$env:UserProfile\OneDrive\AgentVault` |
| macOS OneDrive | `~/Library/CloudStorage/<实际 OneDrive 目录>/AgentVault` |
| macOS NAS | `/Volumes/HomeNAS/AgentVault` |
| Windows NAS | `Z:\AgentVault` |
| Syncthing/Dropbox | 对应软件管理的同步目录下新建 `AgentVault` |

同步软件应满足：

- 所有设备都对目录具有读写权限。
- 文件会双向同步，而不是只做单向备份。
- 不主动转换、压缩或改写 JSON/Markdown 内容。
- 能同步新建目录和小文件。

## 8. 第一台电脑：创建 Vault

### 8.1 使用可视化控制台（推荐）

安装后运行：

```bash
agent-vault ui
```

程序会启动仅限本机访问的 Web 控制台并打开默认浏览器。页面分为三个主要区域：

- **Vault 与同步目录**：显示网盘类型、目录、读写状态、Vault ID、记忆/事件/Skill 数量和最近事件时间。
- **连接新 Vault**：输入路径或调用 macOS/Windows 原生目录选择器；可以连接现有 Vault，也可以勾选后初始化新 Vault。
- **Agent 接入**：显示每个 Agent 是否检测到、是否配置 MCP、是否指向当前 Vault、启动路径是否需要刷新，并提供接入/断开按钮。

控制台还可以一键同步全部共享 Skill。它只检测同步目录，不会登录、控制或读取 iCloud/OneDrive 账号信息。

控制台默认地址：

```text
http://127.0.0.1:47831/
```

指定端口：

```bash
agent-vault ui --port 49000
```

启动但不自动打开浏览器：

```bash
agent-vault ui --no-open
```

临时指定一个已经存在的 Vault：

```bash
agent-vault ui --vault "/path/to/AgentVault"
```

关闭运行控制台的终端或按 `Ctrl+C` 即可停止服务。

“断开本机 Vault”只会取消当前 Vault 选择，已经添加的 Vault 仍保留在“我的 Vault”列表中。“移出列表”也不会删除网盘文件。每个 Agent 的“断开”按钮只移除该 Agent 的 Agent Vault MCP 配置，不删除 Vault、记忆或 Skill 源文件。

### 7.1 多 Vault 管理与手动迁移

控制台会记住每个连接过的 Vault。可以在“我的 Vault”中切换当前 Vault，或仅从本机列表移除。开启自动管理后，切换 Vault 会把已经接入的 Agent 配置刷新到新路径，并每 15 秒进行一次基于内容哈希的 Skill 同步。

“手动迁移”需要明确选择源 Vault 和目标 Vault。迁移会把源 Vault 中目标尚未拥有的不可变记忆事件和 Skill 文件复制到目标；不会删除源文件、不会覆盖冲突文件，也不会改变任一 Vault 的 `vaultId`。迁移可以安全地重复执行。

命令行等价操作：

```bash
agent-vault vaults list
agent-vault vault migrate "/源/Vault" "/目标/Vault"
agent-vault vaults remove "/不再显示的/Vault"
```

安全设计：

- 服务强制只监听回环地址，拒绝 `0.0.0.0`。
- API 需要每次启动随机生成的会话令牌。
- 浏览器请求执行同源检查。
- 页面使用 Content Security Policy，且不加载外部脚本、字体或图片。
- 修改 Agent 配置时继续使用原有时间戳备份机制。

### 8.2 macOS + iCloud Drive

```bash
agent-vault init "$HOME/Library/Mobile Documents/com~apple~CloudDocs/AgentVault" --name "Personal Agent Vault"
```

### 8.3 Windows + OneDrive

```powershell
agent-vault init "$env:OneDrive\AgentVault" --name "Personal Agent Vault"
```

`init` 会：

- 创建 Vault 清单。
- 创建记忆事件目录。
- 创建共享 Skill 目录。
- 自动生成 `agent-vault-memory` Skill。
- 将这个 Vault 设为本机默认 Vault。

检查状态：

```bash
agent-vault status
```

## 9. 接入本机 Agent

### 9.1 先检测 Agent

```bash
agent-vault agents detect
```

如需机器可读结果：

```bash
agent-vault agents detect --json
```

“检测到”表示找到了可执行文件或已有配置文件，不保证 Agent 当前正在运行，也不保证第三方插件依赖已经齐全。

### 9.2 只安装实际使用的 Agent

例如只接入 Codex 和 Cursor：

```bash
agent-vault agents install codex cursor
```

接入所有适配器：

```bash
agent-vault agents install all
```

通常推荐显式列出已安装的 Agent。`all` 会为尚未安装的 Agent 创建配置目录，适合准备标准化电脑环境时使用。

安装器会：

- 在 Agent 配置中增加名为 `agent-vault` 的 MCP Server。
- 将共享 Skill 分发到该 Agent 的 Skill 目录。
- 修改已有配置文件前创建时间戳备份。
- 保留配置文件中的其他 MCP Server 和用户设置。

完成后应重启 Agent，或者至少新建一个 Agent 会话。

### 9.3 Codex 验证

```bash
codex mcp list
```

应看到 `agent-vault` 且状态为 `enabled`。也可以直接检查：

```bash
agent-vault status
agent-vault recall "测试"
```

### 9.4 DeepSeek Harness 注意事项

DeepSeek Harness 适配器会在 `$DSH_HOME/cordis.patch.yml` 中加入使用 `@deepseek-ai/dsh-mcp-client` 的 stdio MCP 行；`DSH_HOME` 未设置时默认使用 `~/.dsh`。

在启用配置之前，应确认目标 DSH profile 已能解析官方 `@deepseek-ai/dsh-mcp-client` 插件。若插件缺失，应先按照当前 DSH 官方文档为该 profile 安装插件。否则 DSH 启动时可能无法解析这一 Cordis 行。

即使 MCP 插件暂时不可用，`~/.agents/skills` 中的共享 Skill 仍可被 DSH 发现，并在 `agent-vault` 命令可用时使用 CLI 回退方式。

控制台会区分 DSH 的两种启动方式：全局安装并能从 `PATH` 找到 `dsh` 时显示“全局命令可用”；曾通过 `npx @deepseek-ai/dsh` 下载到 npm 缓存时显示“npx 方式可用”。因此，后者即使没有全局 `dsh` 命令，也不代表 DSH 无法启动。

### 9.5 MiniMax Code 注意事项

MiniMax Code 适配器使用公开的 Agent Plugins 1.0 接口，不写入已经废弃或不稳定的 `~/.mavis` 配置。接入时会在 `$MINIMAX_DATA_DIR/plugins/agent-vault` 创建本地 Plugin；未设置 `MINIMAX_DATA_DIR` 时默认使用 `~/.minimax/plugins/agent-vault`。

该 Plugin 同时包含 `plugin.json`、`mcp.json`、本机启动器和共享 `skills/`。MiniMax Code 的本地 marketplace 会自动发现这个目录。完成接入或刷新后，应重启 MiniMax Code；命令行版本可用 `mcode plugin list --marketplace local --json` 检查 `agent-vault@local`。

如果只看到“预配置成功 / 未检测到全局命令”，说明 Plugin 已生成，但系统尚未从 `PATH` 找到 `mcode` 可执行文件。安装官方 `@minimax-ai/code` 并重启控制台后会显示“全局命令可用”。

## 10. 第二台及更多电脑

假设第一台电脑已经创建 Vault，并且同步软件已经把完整目录传到第二台电脑。

在第二台电脑上：

1. 使用 Windows 单文件 EXE；或者安装 Node.js 20+ 和 `agent-vault` npm 包。
2. 把 EXE 放到固定位置，或完成 npm 全局安装。
3. 确认 Vault 目录已经下载到本机。
4. 选择现有 Vault，而不是创建另一份独立 Vault。
5. 安装这台电脑上的 Agent 配置。

macOS 示例：

```bash
agent-vault use "$HOME/Library/Mobile Documents/com~apple~CloudDocs/AgentVault"
agent-vault status
agent-vault agents detect
agent-vault agents install codex cursor
agent-vault recall "第一台电脑保存的内容"
```

Windows 示例：

```powershell
agent-vault use "$env:OneDrive\AgentVault"
agent-vault status
agent-vault agents detect
agent-vault agents install codex cursor
agent-vault recall "第一台电脑保存的内容"
```

使用 EXE 时，将上述命令中的 `agent-vault` 换成固定目录中的 `AgentVault.exe`。最简单的方式是双击 EXE，在可视化控制台中选择同步目录并接入 Agent。

每台电脑的 `~/.agent-vault-sync/state.json` 都不同，这是正常现象。不要从第一台电脑复制这个本机状态文件。

## 11. 日常记忆操作

### 11.1 保存记忆

最简单的写法：

```bash
agent-vault remember "用户偏好使用简洁的中文回答"
```

带完整元数据：

```bash
agent-vault remember "项目统一使用 npm，不使用 pnpm" \
  --title "包管理器选择" \
  --kind decision \
  --scope project \
  --scope-id agent-vault-sync \
  --tag node \
  --tag tooling \
  --source-agent codex
```

PowerShell 可以写成一行：

```powershell
agent-vault remember "项目统一使用 npm，不使用 pnpm" --title "包管理器选择" --kind decision --scope project --scope-id agent-vault-sync --tag node --tag tooling --source-agent codex
```

同一个 `--tag` 可以重复多次。

### 11.2 搜索记忆

```bash
agent-vault recall "包管理器"
agent-vault recall "中文偏好" --limit 5
agent-vault recall "部署" --kind lesson --scope project --scope-id agent-vault-sync
```

输出包含相关度分数、记忆 ID、类型和正文。需要交给脚本处理时使用：

```bash
agent-vault recall "包管理器" --json
```

### 11.3 语义检索（可选）

`recall` 和 `context` 默认尝试通过本机 Ollama 生成 Embedding，将语义相似度与现有 Unicode/CJK 文本分数混合。这项能力不依赖托管 Embedding 服务；Ollama 不可用时，搜索会自动回退到文本检索。

可用以下环境变量配置：

| 变量 | 作用 | 默认值 |
|---|---|---|
| `OLLAMA_HOST` | 本机 Ollama 服务地址 | `http://127.0.0.1:11434` |
| `AGENT_VAULT_EMBED_MODEL` | Embedding 模型 | `nomic-embed-text` |
| `AGENT_VAULT_EMBED` | 设为 `off` 时关闭 Embedding | 启用 |
| `AGENT_VAULT_SEMANTIC_WEIGHT` | 语义分数的混合权重 | `1.5` |

临时只用文本检索：

```bash
agent-vault recall "部署方案" --no-semantic
agent-vault context "当前项目约束" --no-semantic
```

Embedding 索引是可丢弃的派生数据，保存在同步 Vault 之外的本机状态目录。每次搜索都会分批修复索引，因此本机写入、网盘同步、手动迁移带来的新增、更新和删除都会自动收敛，不会改写 append-only Vault。

### 11.4 列出记忆

```bash
agent-vault list
agent-vault list --limit 20
agent-vault list --kind decision
agent-vault list --scope project --scope-id agent-vault-sync --tag tooling
```

### 11.5 读取一条记忆

```bash
agent-vault get <memory-id>
agent-vault get <memory-id> --json
```

### 11.6 更新记忆

```bash
agent-vault update <memory-id> --content "项目改为使用 npm 11"
```

同时更新元数据：

```bash
agent-vault update <memory-id> \
  --title "新的标题" \
  --kind decision \
  --scope project \
  --scope-id agent-vault-sync \
  --tag tooling
```

记忆 ID 和最初创建时间保持不变；更新会写入新的事件文件。

### 11.7 忘记一条记忆

```bash
agent-vault forget <memory-id>
```

当前版本会写入删除墓碑，让正常列表和搜索不再显示该记忆。为了保证多设备同步和冲突收敛，旧的事件文件仍然存在，所以这不是安全物理擦除。如果曾误存机密，不能只依赖 `forget`；应立即撤销相关凭据，并人工处理所有设备和云端历史副本。

### 11.8 生成 Agent 上下文

```bash
agent-vault context "当前项目的技术约束"
agent-vault context "用户回答偏好" --limit 8
```

`context` 返回紧凑的文本列表，适合放进 Agent 上下文或调试召回结果。

## 12. 如何让 Agent 使用记忆

完成 MCP 和 Skill 安装后，可以直接对 Agent 说：

- “先从长期记忆中召回与这个项目有关的决定，再开始工作。”
- “请记住：以后这个项目都使用 npm。”
- “把刚才解决问题的方法保存成一条 lesson。”
- “忘记那条关于旧服务器地址的记忆。”
- “列出你能找到的用户回答偏好。”

内置 `agent-vault-memory` Skill 建议 Agent：

- 只召回当前任务真正相关的内容。
- 当前用户指令始终高于历史记忆。
- 保存前先搜索可能的重复项。
- 适合时更新已有记忆，而不是反复新增相同内容。
- 不保存密码、Token、私钥和偶然对话。

是否主动调用工具仍由具体 Agent、模型和安全策略决定。需要确定行为时，应明确要求 Agent 使用 `agent-vault` MCP。

## 13. MCP 工具参考

| 工具 | 类型 | 主要参数 | 作用 |
|---|---|---|---|
| `memory_remember` | 写入 | `content`、`title?`、`kind?`、`scope?`、`scopeId?`、`tags?` | 保存一条长期记忆 |
| `memory_recall` | 只读 | `query`、`limit?`、过滤条件、`semantic?` | 搜索相关记忆 |
| `memory_list` | 只读 | `limit?`、过滤条件 | 列出最近记忆 |
| `memory_get` | 只读 | `id` | 按 ID 读取记忆 |
| `memory_update` | 写入 | `id` 和需要更新的字段 | 更新已有记忆 |
| `memory_forget` | 删除 | `id` | 写入删除墓碑 |
| `memory_context` | 只读 | `query`、`limit?`、`semantic?` | 生成紧凑上下文 |
| `vault_status` | 只读 | 无 | 查看 Vault、记忆和事件数量 |
| `skill_list` | 只读 | 无 | 列出 Vault 中的共享 Skill |

```bash

```

这个命令使用标准输入/输出传输 MCP 协议，不适合当作普通交互命令运行；通常由 Agent 自动启动。

## 14. Skill 复用手册

### 14.1 查看共享 Skill

```bash
agent-vault skills list
```

### 14.2 创建自定义 Skill

在 Vault 中创建：

```text
skills/my-shared-skill/SKILL.md
```

最小内容：

```markdown
---
name: my-shared-skill
description: Describe clearly when an agent should use this skill.
---

# My Shared Skill

Write reusable instructions here.
```

Skill 目录还可以包含：

- `scripts/`：可执行脚本。
- `references/`：按需读取的参考资料。
- `assets/`：模板、图片等资源。

### 14.3 分发 Skill

分发给所有适配器：

```bash
agent-vault skills sync all
```

只分发给指定 Agent：

```bash
agent-vault skills sync codex claude cursor
```

同步逻辑会比较整个 Skill 目录的内容哈希：

- 内容相同：不执行写入。
- 内容不同：替换 Agent 目录中的对应 Skill 副本。
- Vault 中不存在的其他 Agent Skill：不会被删除。

可视化控制台运行且“自动管理”开启时，会每 15 秒把当前 Vault 的 Skill 同步到已连接的 Agent。控制台没有运行时，仍可手动执行 `skills sync`，或点击“同步全部 Skill”。

## 18. 同步和冲突行为

### 18.1 不同记忆同时新增

两台电脑会写入不同设备目录和不同事件文件。同步完成后，两条记忆都会保留。

### 18.2 同一条记忆同时修改

每个事件带有混合逻辑时钟。所有设备按照 `(wallTime, counter, node)` 排序，并以事件 ID 作为最终确定性顺序，最后收敛到同一个版本。

这是 last-write-wins，不是语义合并。重要内容不建议在多台离线设备上同时修改同一个记忆 ID。

### 18.3 删除与旧更新同时发生

删除也是一个事件。最终结果取决于删除和更新事件的逻辑顺序，因此恢复联网后所有设备会确定性收敛。

### 18.4 不完整文件

写入时先创建带 `.pending-*` 后缀的临时文件，再执行原子改名。读取器忽略临时文件和暂时无法解析的同步中 JSON。

### 18.5 同步延迟

Agent Vault Sync 不控制 iCloud、OneDrive 或 NAS 客户端的同步周期。某台设备刚保存的内容需要等同步软件把新事件传到另一台设备后才能召回。

## 19. 数据安全与隐私

### 19.1 当前没有端到端加密

0.5.0 以普通 JSON 和 Markdown 保存数据。任何能读取 Vault 文件夹的人或程序都能读取其中的内容。

不要保存：

- 密码和 PIN。
- API Key、OAuth Token、Cookie。
- SSH/GPG 私钥。
- 钱包助记词和恢复码。
- 身份证件完整号码或高度敏感医疗信息。
- 不适合进入网盘历史版本的公司机密。

### 19.2 建议的基础防护

- 为网盘账号开启多因素认证。
- 使用操作系统磁盘加密，例如 FileVault 或 BitLocker。
- 不把 Vault 放进公开链接或多人可写共享目录。
- 定期检查同步服务的共享成员和登录设备。
- NAS 使用独立账号和最小读写权限。

### 19.3 Prompt Injection 边界

历史记忆只能作为上下文，不能覆盖当前用户指令和 Agent 的系统安全策略。不要把从不可信网页复制的操作指令直接保存为全局记忆。

### 19.4 删除不是物理擦除

`memory_forget` 和 `agent-vault forget` 写入墓碑，不会删除旧事件。网盘历史版本、其他设备缓存和备份也可能保留原文。当前版本尚无安全清除或压缩命令。

### 20.1 备份 Vault

Vault 全部由普通文件组成。可在同步完成且没有正在写入时，复制整个 Vault 目录作为快照备份。

### 20.2 恢复 Vault

恢复后运行：

```bash
agent-vault use "/restored/path/AgentVault"
agent-vault status
agent-vault agents install <使用中的 Agent>
```

### 20.3 Agent 配置备份

安装器修改已有配置前会创建类似下面的文件：

```text
config.toml.agent-vault-backup-2026-08-25T15-52-19-218Z
```

如果 Agent 配置异常，可先关闭 Agent，比较当前文件和备份文件，再恢复需要的内容。不要直接覆盖仍在被 Agent 写入的配置文件。

## 21. 故障排查

### 21.1 `No vault selected`

原因：本机尚未选择默认 Vault，也没有提供路径。

处理：

```bash
agent-vault use "/path/to/AgentVault"
```

或者在命令中添加 `--vault`。

### 21.2 `Not an Agent Vault`

原因：指定目录中没有有效的 `agent-vault.json`，或同步尚未完成。

处理：

- 确认路径指向 Vault 根目录，而不是它的父目录。
- 等待同步软件下载清单文件。
- 第一台电脑使用 `init`；其他电脑优先使用 `use`。

### 21.3 Agent 看不到 MCP 工具

依次检查：

```bash
agent-vault status
agent-vault agents detect
agent-vault agents install <agent-id>
```

然后完全重启 Agent 或新建任务。Codex 可额外运行：

```bash
codex mcp list
```

如果移动过项目或重新安装过 Node.js，重新运行 `agents install` 以刷新绝对路径。

### 21.4 读取工具因审批策略被拒绝

0.5.0 的 recall、list、get、context、status 和 skill list 已标记为只读。应确认 Agent 使用的是最新安装包和最新 MCP 配置：

```bash
agent-vault --version
agent-vault agents install <agent-id>
```

保存、更新、删除是写操作，Agent 仍可能正常要求批准。

### 21.5 Skill 没有出现

```bash
agent-vault skills list
agent-vault skills sync <agent-id>
```

确认 Vault 源 Skill 目录中存在 `SKILL.md`，然后重启 Agent。不要只在 Agent 副本目录中修改 Skill。

### 21.6 搜索不到刚保存的跨电脑记忆

- 先在写入电脑运行 `agent-vault status`，确认事件数量增加。
- 检查网盘或 NAS 是否已经同步新 JSON 文件。
- 在读取电脑确认选择的是同一个 Vault ID。
- 使用正文中真实存在的关键词搜索。
- 检查 `--kind`、`--scope`、`--scope-id`、`--tag` 是否把结果过滤掉。

### 21.7 出现网盘“冲突副本”

不同记忆事件使用唯一文件名，正常情况下不应覆盖。如果同步软件仍生成冲突副本：

- 不要立即删除两份文件。
- 先复制整个 Vault 作为备份。
- 检查两份 JSON 是否都有完整的 `eventId` 和 `memoryId`。
- 保留所有内容完整且文件名以 `.json` 结尾的独立事件；读取器会合并不同事件。

### 21.8 DeepSeek Harness 启动时报插件找不到

原因通常是目标 profile 尚未安装或无法解析 `@deepseek-ai/dsh-mcp-client`。

处理：

- 先按照 DSH 当前官方文档安装 MCP Client 插件。
- 使用 DSH 的配置 dump 功能检查 `agent-vault-mcp` 行是否成功组合。
- 如果暂时不使用 MCP，可运行 `agent-vault agents uninstall deepseek-harness` 移除该配置，同时保留共享 Skill 和 CLI。

### 21.9 JSON 配置无法解析

安装器要求相关 Agent 配置是有效 JSON。可使用安装器创建的时间戳备份恢复，然后修复原配置中的注释、尾随逗号或截断内容，再重新安装适配器。

## 22. 卸载

先移除 Agent MCP 配置：

```bash
agent-vault agents uninstall all
```

再卸载全局 npm 包：

```bash
npm uninstall -g agent-vault-sync
```

Vault、记忆和已复制的 Skill 不会自动删除。是否保留这些数据应由用户单独决定。

如果未来重新安装，只需要对已有 Vault 执行：

```bash
agent-vault use "/path/to/AgentVault"
agent-vault agents install <agent-id>
```

## 23. 当前限制与后续方向

0.5.0 已实现 CLI、MCP、Skill、多 Vault 管理、手动迁移和可视化管理主链，但仍有明确限制：

- 没有端到端加密和密钥管理。
- 没有安全物理删除和事件压缩。
- 自动 Skill 分发依赖可视化控制台保持运行；尚未提供操作系统级后台服务。
- 搜索每次扫描事件文件，适合个人规模，不适合数百万事件。
- 没有可用的本机 Ollama 服务时，召回仅使用 Unicode/CJK 文本匹配，同义词召回能力有限。
- 同一记忆并发修改采用 LWW，不做文本语义合并。
- Agent 配置格式会随上游版本变化，需要持续维护适配器。
- Windows 已实现兼容代码和 CI 配置，仍需要更多实机验收。
- Windows x64 已提供单文件 EXE；当前没有商业代码签名和图形子系统外壳，双击时会同时保留一个控制台窗口。

在不增加服务器成本的前提下，优先级较高的后续能力是：

1. 进一步优化大型 Vault 的事件扫描和索引刷新性能。
2. 操作系统级后台服务与原生文件事件监听。
3. 事件压缩、归档和受控物理删除。
4. 可选端到端加密，而不是强制所有用户承担密钥管理成本。
5. 更多 Agent 适配器和 Windows 实机安装程序。

## 24. 获取帮助时应提供的信息

报告问题时，建议提供：

- 操作系统和版本。
- Node.js 与 `agent-vault` 版本。
- 使用的 Agent 和版本。
- `agent-vault status --json` 输出，但先检查其中是否包含不想公开的路径。
- `agent-vault agents detect --json` 输出。
- 相关错误消息。
- 使用的同步方式，例如 iCloud、OneDrive、Syncthing 或 NAS。

不要在问题报告中附带 Vault 全量内容、凭据或包含隐私的记忆事件。
